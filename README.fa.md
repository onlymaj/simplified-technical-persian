# فارسی فنی ساده

**[فارسی](README.fa.md)** · **[English](README.md)**

یک مهارت (skill) برای Claude Code که متن فنی فارسی را چنان بازنویسی می‌کند که فقط یک خوانش درست داشته باشد. این مهارت نظم استاندارد `ASD-STE100` (انگلیسی فنی ساده) را به فارسی می‌آورد. قاعده‌های انگلیسی را ترجمه نمی‌کند؛ هر قاعده را با اصطلاح‌های دستور زبان فارسی از نو می‌نویسد و قاعده‌هایی را می‌افزاید که فارسی به آن‌ها نیاز دارد و انگلیسی ندارد.

## چرا

استاندارد `ASD-STE100` دو منبع اصلی بدخوانی در انگلیسی را حذف می‌کند: واژه‌های چندمعنایی و جمله‌های چندساختاری. فارسی به دلایل دیگری بد خوانده می‌شود:

- **اضافهٔ نامرئی.** کسرهٔ اضافه معمولاً نوشته نمی‌شود. پس بیشتر پیوندهای اسم و وابسته در متن نشانه‌ای ندارند و زنجیرهٔ اضافه (تتابع اضافات) چندین خوانش می‌پذیرد.
- **چندمعنایی «شدن».** «شدن» هم فعل کمکی مجهول است، هم فعل اصلی به معنی «گردیدن»، هم سازندهٔ فعل مرکب معلوم. یک قاعدهٔ مکانیکی مانند «از مجهول پرهیز کن» موردهای نادرست را علامت می‌زند.
- **اسم‌سازی اداری.** «مورد استفاده قرار دادن» هم کنش را پنهان می‌کند، هم کنشگر را.
- **نیم‌فاصله (ZWNJ).** کاربرد ناهمسان نیم‌فاصله جست‌وجو، مرتب‌سازی و صفحه‌خوان را خراب می‌کند.
- **شکستن دوسویه‌نویسی (bidi).** اصطلاح انگلیسی، کد و عدد در میان متن راست‌به‌چپ، اگر جدا نشوند، در جای نادرست نمایش داده می‌شوند.

هیچ استاندارد رسمی برای «فارسی کنترل‌شده» وجود ندارد. این مهارت چنین استانداردی را از مرجع‌های موجود می‌سازد: دستور خطّ فارسی (ویراست ۱۴۰۱)، فرهنگ املایی خطّ فارسی، اصول و ضوابط واژه‌گزینی، راهنمای سبک مایکروسافت برای `fa-IR` و شیوهٔ کار مستندات حرفه‌ای فارسی.

## نصب در Claude Code

مخزن را کلون کنید. سپس آن را به پوشهٔ مهارت‌های خود پیوند بدهید:

```bash
git clone <this-repo> ~/projects/asd-ste100
ln -s ~/projects/asd-ste100 ~/.claude/skills/persian-technical-writing
```

یا مهارت را فقط در یک پروژه کپی کنید:

```bash
mkdir -p .claude/skills && cp -R ~/projects/asd-ste100 .claude/skills/persian-technical-writing
```

## نصب در عامل‌های دیگر

قاعده‌ها به هیچ عامل خاصی وابسته نیستند. فقط بسته‌بندی آن‌ها فرق می‌کند. بیشتر عامل‌ها فایل مارک‌داون ساده می‌پذیرند. پس یک فایل، یعنی `rules/system-prompt.md`، همهٔ آن‌ها را پوشش می‌دهد. آن را کپی کنید و به نامی که ابزار شما می‌خواهد تغییر نام بدهید:

| ابزار | این فایل را کپی کنید | به این مسیر |
|---|---|---|
| Codex، Aider، Zed، Jules، Gemini CLI، Amp | `rules/system-prompt.md` | `AGENTS.md` |
| Cline، Roo Code | `rules/system-prompt.md` | `.clinerules/persian-technical-writing.md` |
| GitHub Copilot | `rules/system-prompt.md` | `.github/copilot-instructions.md` |
| هر مدل گفت‌وگویی، Custom GPT، Gem، فراخوان API | `rules/system-prompt.md` | همان system prompt |
| Cursor | `rules/cursor.mdc` | `.cursor/rules/persian-technical-writing.mdc` |
| Windsurf | `rules/windsurf-persian-script.md` | `.windsurf/rules/persian-script.md` |
| | `rules/windsurf-persian-structure.md` | `.windsurf/rules/persian-structure.md` |

فقط دو ابزار فایل جداگانه می‌خواهند: Cursor به فرادادهٔ MDC نیاز دارد و Windsurf هر فایل قاعده را به حدود ۶٬۰۰۰ نویسه محدود می‌کند. پس قاعده‌ها آنجا به دو فایل بخش می‌شوند. فایل `rules/README.md` یادداشت هر ابزار را دارد: چرا قاعدهٔ Cursor به‌جای «همیشه فعال» به تصمیم عامل واگذار شده، چگونه فایل Copilot را به مسیرهای فارسی محدود کنید، و فشرده‌سازی Windsurf چه چیزی را کنار می‌گذارد.

استفاده از درون کد:

```python
RULES = open("rules/system-prompt.md", encoding="utf-8").read()
client.messages.create(model="claude-sonnet-5", max_tokens=2000,
                       system=RULES + "\n\nMode: Strict.",
                       messages=[{"role": "user", "content": persian_text}])
```

این قاعده‌ها نام هیچ سازنده‌ای را نمی‌برند و به ابزار نیاز ندارند. پس همین رشته در `system` مدل‌های OpenAI و در `system_instruction` مدل‌های Gemini هم کار می‌کند.

## استفاده

وقتی ساده‌سازی متن فارسی را بخواهید، Claude خودش این مهارت را به کار می‌گیرد. می‌توانید آن را با نام هم صدا بزنید:

```
/persian-technical-writing

این پاراگراف را ساده کن: ...
```

درخواست‌هایی که این مهارت را فعال می‌کنند:

- «این متن را ساده‌نویسی کن»، «فارسی روان بنویس»، «ویرایش فنی»
- «این سند فارسی را طوری بازنویسی کن که عامل هوشمند بد نخواند»
- «نیم‌فاصله و اعداد این صفحه را یکدست کن»

### دو حالت

| حالت | برای چه متنی | چه قاعده‌هایی |
|---|---|---|
| **سخت‌گیرانه (Strict)** | دستورالعمل، پیام خطا، شرح ابزار و تابع، دستور میان‌عاملی، متن ایمنی | همهٔ قاعده‌ها: سقف طول جمله، منع نقطه‌ویرگول، یک واژه برای یک معنا |
| **روان (Flavored)** | README، سند توضیحی، تغییرنامه، متن آموزشی | قاعده‌های ساختاری و خطی به‌طور کامل؛ قاعده‌های واژگانی توصیه‌ای؛ «؛» به‌ندرت مجاز |

**قاعده‌های خط هرگز اختیاری نیستند.** نیم‌فاصله، نویسه‌های فارسی (ی با کد U+06CC و ک با کد U+06A9)، ارقام فارسی، نشانه‌گذاری و جداسازی دوسویه در هر دو حالت اجرا می‌شوند. این‌ها قاعدهٔ درستی هستند، نه سلیقهٔ سبک.

### خروجی

مهارت به‌طور پیش‌فرض فقط متن بازنویسی‌شده را چاپ می‌کند: بدون مقدمه و بدون شمار خطاها. اگر دلیل تغییرها را بخواهید («تفاوت‌ها را نشان بده»)، به‌جای متن، جدول قاعده‌ها را می‌دهد:

| قاعدهٔ نقض‌شده | متن اصلی | متن ساده‌شده |
|---|---|---|
| اسم‌سازی اداری | «مورد بررسی قرار خواهد گرفت» | «بررسی می‌شود» |
| زنجیرهٔ اضافه (۴+) | «تنظیمات صفحهٔ مدیریت کاربران سامانه» | «تنظیمات مدیریت کاربران در سامانه» |

## چه چیزی را بررسی می‌کند

هشت بررسی مکانیکی. هر کدام به واژه یا نویسهٔ دقیق اشاره می‌کند:

- **۱. اسم‌سازی اداری**: «مورد … قرار دادن»، «به عمل آوردن»، «اقدام به … نمودن»
- **۲. چرخش مترادف**: کاربر، مشتری و استفاده‌کننده برای یک مرجع
- **۳. لحن «می‌باشد»**: می‌باشد، بدین‌وسیله، مذکور، ذیل
- **۴. زنجیرهٔ «که» و «و»**: چند ایده در یک جمله
- **۵. انباشت اضافه**: چهار پیوند یا بیشتر
- **۶. بهداشت خط**: ي و ك عربی، ارقام لاتین در متن فارسی، «می رود»، «میرود»، «کتابها»
- **۷. انباشت تردید**: «شاید بتوان گفت که احتمالاً ممکن است»
- **۸. شکستن دوسویه‌نویسی**: اصطلاح انگلیسی، کد یا عدد بدون نشانه‌گذاری جهت

## محدوده

**انجام می‌دهد:** فارسی اداری یا مبهم را به جملهٔ کوتاه، تک‌معنا و معلوم بازمی‌نویسد؛ قاعده‌های خط را در هر دو حالت یکدست می‌کند؛ هر واقعیت، شرط، قید محدوده و نشانهٔ تردید را نگه می‌دارد.

**انجام نمی‌دهد:** ادعای تأیید فرهنگستان نمی‌کند؛ فعل مرکب را ممنوع نمی‌کند؛ هر «شدن» را مجهول نمی‌شمارد؛ متن تبلیغاتی و ادبی را ساده نمی‌کند؛ برای کوتاه‌کردن جمله، شرط ایمنی را حذف نمی‌کند؛ و متن بی‌محتوا را درست نمی‌کند. فارسی کنترل‌شده *شکل* متن را اصلاح می‌کند، نه محتوای آن را.

## فایل‌ها

| مسیر | چیست |
|---|---|
| `SKILL.md` | **یگانه منبع اصلی**: قاعده‌ها، سیاههٔ بررسی، فرایند، قالب خروجی، مرزها. مهارت Claude Code هم همین است |
| `references/research-report.md` | پژوهش مستند پشت هر قاعده: کدام ادعا راستی‌آزمایی خصمانه شده، کدام تک‌منبع است و کدام رد شده است |
| `rules/` | همین قاعده‌ها، بسته‌بندی‌شده برای عامل‌های دیگر |
| `AGENTS.md` | راهنمای عامل‌هایی که روی *خودِ* این مخزن کار می‌کنند |

`SKILL.md` مرجع است و `rules/` رونوشت‌های دستی آن را نگه می‌دارد. قاعده را در `SKILL.md` تغییر بدهید و همان تغییر را در `rules/` هم بیاورید. فایل `rules/system-prompt.md` عین متن کامل است، پس رونوشت مستقیم می‌گیرد. دو فایل Windsurf برای جاشدن در سقف نویسه‌های آن ابزار فشرده شده‌اند، پس باید دوباره فشرده شوند.

گزارش پژوهش دربارهٔ میزان اطمینان صادق است: دو ادعا که سقف طول جمله را پشتیبانی می‌کردند، در راستی‌آزمایی **رد شدند**. پس این سقف‌ها به‌عنوان تصمیم طراحی برگرفته از `ASD-STE100` ثبت شده‌اند، نه به‌عنوان معیاری که برای فارسی اعتبارسنجی شده باشد.

## پیشینه

انطباق یک زبان کنترل‌شده با زبانی دیگر تازه نیست. انجمن هوافضای فرانسه «فرانسهٔ عقلانی‌شده» (le Français Rationalisé) را ساخت تا با انگلیسی سادهٔ AECMA جفت شود. هدف آن دوگانه بود: نگاشت آسان به انگلیسی ساده *و* خوانایی بهتر برای خوانندهٔ بومی فرانسوی. کارگروه آن از سال ۱۹۸۵ تا انتشار در سال ۱۹۹۹ میلادی کار کرد. این مهارت همان موضع را برای فارسی می‌گیرد: اول خوانندهٔ بومی.
